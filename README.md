# Score Clipper

커버 영상(드럼·기타·베이스 등) 하단에 몇 마디씩 표시되는 악보를 자동으로 잘라내
전체 악보 한 장(PNG/PDF)으로 이어붙인다.

## 동작 원리 (v4, 웹앱·CLI 공통)

1. 영상을 일정 간격(기본 0.5초)으로 샘플링해 악보 띠 영역만 크롭하고, 폭 1920px로 맞춘다
2. 픽셀을 잉크(어둡고 무채색) / 종이(밝고 무채색) / 불확실(컬러 하이라이트, 흐린 경계)로 나눈다
3. 지금 페이지의 기준 이미지(표본들의 잉크/종이 다수결)와 비교해
   "종이였던 곳에 생긴 잉크 + 종이로 바뀐 잉크" 픽셀 수가 40을 넘으면 페이지 넘김 후보
4. 연속 2표본이 같은 새 페이지를 보여줄 때만 넘김으로 확정 (전환 잔상 제거)
5. 페이지마다 최대 7프레임을 65퍼센타일로 합성해 움직이는 마디 하이라이트를 지운다
6. 세로로 이어붙여 출력

설계 근거 (2026-10-20 실측):

- 같은 페이지 안의 잡음 0~13px, 마디 번호만 다른 페이지 사이 차이 79px 이상 → 문턱 40
- 컬러 하이라이트는 "불확실"로 빠져 판정에 영향이 없다
- 크롭에 영상이 섞이면 잡음이 생긴다. 추출 전 사전 스캔(영상 전체에서 0.5초 간격 프레임 쌍)으로
  "페이지가 안 넘어가는데도 바뀌는 행"을 찾아 판정에서 빼고, 추출 중에도 자주 바뀌는 16px 블록을 뺀다
- 악보가 떠 있는지(인트로·아웃트로 제외)는 원본 해상도로 판정한다: 밝은 영역 55% 이상 + 잉크 0.2% 이상.
  축소본으로 세면 음표가 드문 페이지(잉크 0.07%)를 통째로 놓친다 (v3까지의 버그)

제약:

- 페이지 넘김 방식 전용. 연속 스크롤 악보는 미지원
- 마디 번호가 없는 영상에서 완전히 같은 페이지가 연달아 나오면 구분할 수 없다

## 웹앱 (index.html)

- 배포: https://score-clipper.vercel.app (Vercel, GitHub main 푸시 시 자동 배포)
- 서버 없는 정적 페이지. 영상은 브라우저 밖으로 전송되지 않음
- 로컬 실행: `python3 -m http.server 8765` 후 http://localhost:8765
- 테스트 훅: `?src=파일URL` 쿼리로 자동 로드 (같은 출처 파일)

### 파일 업로드 모드

영상 파일 업로드 -> 악보 영역 드래그 지정 -> 추출 -> PNG 다운로드 / PDF 저장 / 인쇄

### 유튜브 링크 모드 (베타, PC Chrome·Edge 전용)

링크 붙여넣기 -> 화면 공유 연결("이 탭" 선택) -> 악보 영역 지정 -> 추출

- 유튜브 원본은 브라우저에서 받을 수 없어서(CORS), 페이지에 임베드한 플레이어를 화면 공유
  (`getDisplayMedia` + Region Capture `cropTo`)로 캡처해 읽는다. 서버 없음
- 영상을 실제로 재생하므로 2배속 기준 영상 길이의 절반 정도 걸린다
- 유튜브는 재생 초반 몇 초를 저화질로 보여주므로, 영상 중간에서 hd1080까지 올린 뒤 처음으로 되감는다
- 탐색·배속 변경 직후 플레이어가 공유·더보기 버튼을 4~5초 띄운다. 버튼 자리는 판정에서 빼고,
  되감은 직후 6초 동안의 표본은 합성에서 뺀다 (깨끗한 표본이 있으면)
- 서버에서 yt-dlp를 돌리는 방식은 유튜브가 데이터센터 IP를 막아서 쓰지 않는다 (v3에서 시도 후 제거)

## CLI (cli/score_stitch.py)

유튜브 URL부터 한 번에 처리할 때 사용 (yt-dlp + ffmpeg 필요).
페이지 넘김 감지는 웹앱과 같은 v4 방식이다 (위 "동작 원리"의 3분류·문턱 40px·연속 2표본 확정·사전 스캔·움직임 블록 제외·인접 같은 페이지 병합).

```
yt-dlp --no-playlist -f "bv*[height<=1080][ext=mp4]" -o video.mp4 "<URL>"
pip install -r cli/requirements.txt
python cli/score_stitch.py video.mp4 --y 940 --height 140 --fps 2 --out score_out
```

- `--y`, `--height`: 악보 띠의 시작 y좌표와 높이(px). 프레임 하나 뽑아서 확인 후 지정. 가로는 항상 화면 전체 폭
- `--fps`: 초당 표본 수. 기본 2(0.5초 간격)로 웹앱 권장값과 같다
- `--min-white`, `--min-ink`: 악보가 떠 있는 프레임 판정 기준. 기본 0.55 / 0.002로 웹앱과 같다. 악보를 못 찾을 때만 조정
- 실행 중 판정 행 범위, 같은 페이지 최대 차이, 넘김 최소 차이(px)를 출력한다. 넘김 최소 차이가 문턱 40에 가까우면 결과의 마디 번호를 직접 확인한다
- v2의 `--page-diff`, `--min-run` 옵션은 없앴다 (문턱 40px, 최소 2표본으로 고정)
- 결과: `full_score.png`, `full_score.pdf`, 추출 프레임 `strips/` (다 쓰면 지워도 된다)
